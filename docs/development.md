# 工作原理、已知限制与测试

[← 返回 README](../README.md)

## 工作原理

```text
连上手机，锁着屏就自动解开
（连不上会在 20 秒内重试几次；解不开锁、配置错误这类重试没用的直接说明原因）
        ↓
决定玩什么（文本模型：人设 + 时间 + 最近玩过 + 她记得的内容 + 白名单应用；自动玩时还有麦生活的日程）
        ↓
循环：锁屏了先解开 → 截图 → 检查前台应用是否在白名单 → 读取界面元素并在截图上编号
      → 视觉模型输出一个 JSON 动作 → 通过 adb（安卓）或 WebDriverAgent（iPhone）执行 → 等待画面变化
        ↓
玩够时间 / 达到步数或模型调用预算 / 她自己说不玩了 / 卡住了 / 被叫停
        ↓
回桌面、锁屏 → 记录这次玩了哪些应用、调用了几次模型 → 在聊天里提一句或交给麦生活分享
```

- 设备层是可替换的（`devices.py` 的 `PhoneDevice`）：安卓走 adb，iPhone 走 WebDriverAgent（`device.backend = "ios_wda"`）。
- 坐标使用 0～1000 的相对坐标，宿主为了适配模型缩放截图也不会错位；普通应用优先按元素编号点击，游戏、视频等读不到界面元素的画面只用坐标。

## 已知限制

- **快节奏游戏玩不了**：每一步需要 3～10 秒（截图 + 识图 + 执行）。适合刷视频、逛帖子、听歌、看小说和休闲点击类游戏。
- **安卓读界面会失败**：`uiautomator dump` 在视频播放等画面不停变化时经常失败，这时只靠坐标点击，准确度取决于视觉模型。走无线调试时读一次界面约 5 秒，比截图和执行慢不少。
- **iPhone 读界面不判断可见性**：读界面元素时不让 WDA 判断元素是否可见（这一项能让一次读取从几秒变成零点几秒），插件只能按位置推断：键盘和盖在上面的列表挡住的会去掉，弹窗下面的按钮偶尔还会列出来；她同时看着截图，一般不影响。
- **iPhone 点击慢一些**：每次点击要将近 1 秒（WDA 模拟触摸本身的耗时）。
- **iPhone 只按竖屏处理**：横屏游戏的坐标可能对不上。
- **模型调用次数只算插件自己发出的请求**：宿主内部的自动重试插件看不到，不算进次数和预算。token 只在宿主返回了用量时才统计，没返回时显示「未提供」，不会用估算值冒充。
- **给不出前台应用的设备**：白名单只能靠打开应用时检查，玩的途中被带到别的应用时拉不回来。
- **内容记忆可能记错**：只记模型说自己确定的名字，模型也可能认错；记错了在 WebUI 里删掉就行。
- **视频长短靠模型分辨**：短视频、长视频由模型看画面分辨，代码不检查；视频播完了插件看不出来，她会看满自己定的时间。

```bash
uv run pytest plugins/phone_play/tests -q
```

## 联调

接上手机后按这几步走一遍：

1. 安卓：`adb devices` 能看到设备；iPhone：`http://127.0.0.1:8100/status` 显示 `ready`。WebUI「手机实时画面」里能看到手机屏幕。
2. 私聊发 `/手机截图`，应收到当前画面。
3. 发 `/手机 开始 刷B站看猫猫`，在 WebUI 里看操作记录和她的想法；第一次建议盯着看几步，确认模型点得准。
4. 发 `/手机 停止`，应立即停下，并在聊天里收到这次玩了什么。
5. 在手机上手动打开「设置」，下一步应被自动带回桌面。
